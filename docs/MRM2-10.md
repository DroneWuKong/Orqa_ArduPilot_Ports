# MRM2-10 AI compatibility status

**As of 20 November 2026: the owner reports repeated flights with the installed
4.8.0-dev image; the repository's separate 4.7.2 image has not been flown.**
This is a dated status for one MRM2-10 AI, not a release claim for every Orqa
APB.

## What this repository builds

The `apb-copter` target builds ArduCopter 4.7.2 for the mixed MPU6000/ICM42605
population. The separate `apb-dual-icm42605-copter` target is a 4.7.2
candidate for the two ICM42605s observed on this unit. Both use the pinned
source in [`upstream.lock.json`](../upstream.lock.json). They follow the same
experimental, hardware-unvalidated prerelease policy. Compilation and APJ
checks do not establish that either image flies on this MRM2-10. See the
[dual-ICM42605 evidence and checks](APB-DUAL-ICM42605.md).

The APB board ID `1189` collides with upstream CORVON743V1. Verify the Orqa
USB identity `35b6:0090`, actual sensor population, bootloader and physical
axes before selecting an image; board ID alone is insufficient. The
`OrqaAPB-ICM42688` target is a different sensor-population variant.

## Fielded MRM2-10

A read-only check of the MRM2-10 on 20 November found ArduCopter 4.8.0-dev
`0922bced`, board ID `1189` and Orqa USB `35b6:0090`. This is a **different
source revision** from the build in this repository. The retained fielded
board definition differs from this overlay in IMU rotations, default logging
and optional sensor features. The owner reports repeated flights with this
image. The exact installed application is published as a
[separate 4.8.0-dev readback prerelease](https://github.com/DroneWuKong/Orqa_ArduPilot_Ports/releases/tag/mrm2-10-4.8.0-dev-0922bced-readback).
Its original compiler and complete build inputs were not recovered, so the
tagged repository source does not rebuild that APJ. The public 4.7.2 artifacts
are not interchangeable updates for that aircraft.

The per-airframe FC settings and tune are held in a restricted Orqa review
package. They are observed values, not board defaults, and are intentionally
not included in public firmware artifacts. A recent flight-log review found
increased accelerometer clipping; no PID change was justified from that log.
That finding remains open despite the reported flights.

## Before considering an MRM2-10 firmware update

1. Reconcile the exact fielded source, board definition, bootloader layout and
   parameter migration with the proposed image. Compare both IMU rotations
   against the actual marked chips and physical axes.
2. Preserve a complete current parameter backup, missions, logs and a tested
   exact-image recovery path. Review motor outputs, receiver, battery and
   failsafe settings against the installed wiring.
3. Run the [propellers-off acceptance checks](TESTING.md), then resolve the
   vibration finding and obtain a clean repeat log before claiming the 4.7.2
   image has been flight-validated on this aircraft.

Software build success, flights on a different image and a settings snapshot
each answer a different question. None alone qualifies the 4.7.2 image for
flight on this airframe.
